## Enhanced

### 1. User Story
**Como** usuario
**Quiero** iniciar sesión con mi correo electrónico y contraseña o a través de mi cuenta de Google
**Para** acceder de forma segura a mi cuenta y visualizar mi dashboard.

### 2. Descripción de la Funcionalidad (Flow)
El sistema debe permitir a los usuarios autenticarse proporcionando sus credenciales o usando un proveedor externo (Google).
#### Flujo de Credenciales:
1. El usuario ingresa su email y contraseña en el formulario de login.
2. El sistema valida que los campos cumplan con los formatos requeridos.
3. El sistema busca al usuario por email y verifica la contraseña usando un hash seguro.
4. Si las credenciales son válidas, se genera un token de sesión (JWT) y se retorna al cliente.
5. El usuario es redirigido a su dashboard.
6. Si las credenciales son incorrectas o el usuario no existe, el sistema devuelve un error genérico pero seguro (ej. "Invalid email or password").

#### Flujo de Google OAuth:
1. El usuario hace clic en "Iniciar sesión con Google".
2. El frontend redirige al usuario a la pantalla de consentimiento de Google.
3. Tras la autorización, Google devuelve un token al frontend, que lo envía al backend.
4. El backend valida el token con Google.
5. Si el usuario no existe en la base de datos, se crea automáticamente (registro).
6. Se genera un token JWT propio de la aplicación y se devuelve al cliente.

#### Flujo de Verificación de Sesión (`GET /me`):
1. Al cargar o refrescar la aplicación frontend, se realiza una petición automática al backend para validar el estado de la sesión.
2. El navegador envía de forma transparente la cookie HttpOnly `token`.
3. El backend verifica la autenticidad del JWT y realiza un lookup asíncrono en la base de datos a través del repositorio de usuarios.
4. Si la sesión es válida, el backend retorna los datos del usuario (id, email, nombre, rol) y el frontend renderiza el Dashboard.
5. Si no hay cookie o la verificación falla, se deniega el acceso y el usuario permanece en la pantalla de Login.

#### Flujo de Cierre de Sesión Seguro (`POST /logout`):
1. El usuario hace clic en el botón de cerrar sesión en el Dashboard.
2. El frontend realiza una petición POST al endpoint de logout del backend.
3. El backend elimina la cookie de sesión enviando la cabecera `Set-Cookie` con `Max-Age=0` y las propiedades `HttpOnly` y `SameSite=Strict`.
4. El frontend limpia el estado global de autenticación (`AuthContext`) y redirige al usuario a la pantalla de Login.

### 3. Lista Completa de Campos
*   `email`: String, requerido, formato de email válido.
*   `password`: String, requerido para flujo tradicional (mínimo 8 caracteres).
*   `idToken`: String, requerido para flujo de Google OAuth.

### 4. Estructura de Endpoints y URLs

#### 4.1 Autenticación Tradicional: `POST /api/auth/login`
- **Request Body**:
```json
{
  "email": "user@example.com",
  "password": "yourpassword"
}
```
- **Success Response (200 OK)**:
  - **Headers**: `Set-Cookie: token=<jwt_token_string>; HttpOnly; SameSite=Strict; Secure (in prod)`
  - **Response Body**:
```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "user": {
      "id": 1,
      "email": "user@example.com",
      "name": "User Name",
      "role": "user"
    }
  }
}
```

#### 4.2 Autenticación con Google: `POST /api/auth/google`
- **Request Body**:
```json
{
  "idToken": "google_id_token_string"
}
```
- **Success Response (200 OK)**:
  - **Headers**: `Set-Cookie: token=<jwt_token_string>; HttpOnly; SameSite=Strict; Secure (in prod)`
  - **Response Body**:
```json
{
  "success": true,
  "message": "Google login successful",
  "data": {
    "user": {
      "id": 1,
      "email": "user@example.com",
      "name": "User Name",
      "role": "user"
    }
  }
}
```

#### 4.3 Obtención de Perfil de Sesión: `GET /api/auth/me`
- **Request Headers**: Debe incluir automáticamente la cookie segura `token`.
- **Success Response (200 OK)**:
```json
{
  "success": true,
  "message": "User retrieved successfully",
  "data": {
    "user": {
      "id": 1,
      "email": "user@example.com",
      "name": "User Name",
      "role": "user"
    }
  }
}
```

#### 4.4 Cierre de Sesión Seguro: `POST /api/auth/logout`
- **Success Response (200 OK)**:
  - **Headers**: `Set-Cookie: token=; HttpOnly; SameSite=Strict; Max-Age=0`
  - **Response Body**:
```json
{
  "success": true,
  "message": "Logged out successfully",
  "data": null
}
```

#### 4.5 Respuestas de Error Comunes
- **Error de Validación (400 Bad Request)**:
```json
{
  "success": false,
  "message": "Password must be at least 8 characters",
  "data": null
}
```
- **Error de Credenciales (401 Unauthorized)**:
```json
{
  "success": false,
  "message": "Invalid credentials",
  "data": null
}
```
- **Error de Límite de Peticiones (429 Too Many Requests)**:
```json
{
  "success": false,
  "message": "Too many requests, please try again later.",
  "data": null
}
```
