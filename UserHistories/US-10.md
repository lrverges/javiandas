### 1. User Story
**Como** Administrador de Empresa
**Quiero** deshabilitar a un empleado de la plataforma
**Para** controlar quiénes acceden al beneficio de las viandas corporativas.

### 2. Descripción de la Funcionalidad (Flow)
El sistema debe permitir a un Administrador de Empresa dar de baja a un empleado y gestionar qué ocurre con los pedidos que dicho empleado ya había programado a futuro (generados en **US-08**).
#### Flujo Principal:
1. El Administrador ingresa al listado de empleados de su empresa y hace clic en "Deshabilitar" sobre un usuario.
2. El frontend solicita al backend el estado de los pedidos futuros del empleado.
3. El sistema intercepta la acción y despliega un modal informando sobre los pedidos activos futuros.
4. El modal ofrece tres opciones:
   - "Cancelar todos": Cancela todos los pedidos futuros.
   - "Mantener todos": Mantiene los pedidos tal cual están.
   - "Selección manual": Permite tildar/destildar qué pedidos mantener y cuáles cancelar.
5. El Administrador confirma la acción.
6. El backend cambia el estado del usuario a inactivo (lo que bloqueará su futuro login, según **US-01**).
7. El backend actualiza el estado de los pedidos según la selección.
8. El sistema registra automáticamente una notificación en el panel de alertas de Javiandas (**US-11**) detallando qué pedidos fueron modificados o mantenidos.

### 3. Lista Completa de Campos
*   `employeeId`: Integer, requerido, identificador del empleado.
*   `action`: Enum (`cancel_all`, `keep_all`, `manual`), requerido.
*   `manualSelection`: Array de Integers (IDs de pedidos), requerido si `action` es `manual`.

### 4. Estructura de Endpoints y URLs

#### 4.1 Obtener pedidos futuros del empleado: `GET /api/companies/employees/:id/future-orders`
- **Success Response (200 OK)**:
```json
{
  "success": true,
  "data": {
    "orders": [
      { "id": 101, "date": "2026-05-20", "dishName": "Milanesa con puré" },
      { "id": 102, "date": "2026-05-21", "dishName": "Tarta de verdura" }
    ]
  }
}
```

#### 4.2 Deshabilitar empleado: `POST /api/companies/employees/:id/deactivate`
- **Request Body**:
```json
{
  "action": "manual",
  "manualSelection": [101]
}
```
- **Success Response (200 OK)**:
```json
{
  "success": true,
  "message": "Empleado deshabilitado y pedidos actualizados correctamente."
}
```

### 8. Requerimientos No Funcionales
