### 1. User Story
**Como** Usuario (Particular o Empleado)
**Quiero** gestionar mis direcciones de entrega y elegir una predeterminada
**Para** agilizar el proceso de envío y recibir las viandas en el lugar correcto.

### 2. Descripción de la Funcionalidad (Flow)
#### Flujo de Gestión de Direcciones:
1. El usuario accede a la sección "Mis Direcciones".
2. Ve la lista de sus direcciones guardadas.
3. Puede agregar una nueva completando: Calle, Altura, Localidad y Referencia ("Casa", "Oficina").
4. Si el usuario es corporativo, el frontend/backend valida la regla `allowExtraAddresses` de la empresa (configurada en **US-02**). Si es `false`, se bloquea la creación de nuevas direcciones y solo puede usar la de la empresa.
5. El usuario puede marcar una dirección como "Predeterminada" mediante un radio button o botón de estrella.
6. Al marcar una como predeterminada, el backend actualiza automáticamente, quitándole esa marca a cualquier otra. La dirección predeterminada es clave para armar la Hoja de Ruta (**US-13**).

### 3. Lista Completa de Campos
*   `street`: String, requerido.
*   `number`: String, requerido.
*   `locality`: String, requerido.
*   `reference`: String, requerido.
*   `isDefault`: Boolean.

### 4. Estructura de Endpoints y URLs

#### 4.1 Obtener direcciones: `GET /api/users/me/addresses`
- **Success Response**:
```json
{
  "success": true,
  "data": [
    { "id": 1, "street": "Av Belgrano", "number": "100", "locality": "Lules", "reference": "Casa", "isDefault": true }
  ]
}
```

#### 4.2 Agregar dirección: `POST /api/users/me/addresses`
- **Request Body**:
```json
{
  "street": "San Martin", "number": "450", "locality": "Lules", "reference": "Trabajo 2"
}
```

#### 4.3 Marcar como predeterminada: `PUT /api/users/me/addresses/:addressId/default`
- **Success Response**:
```json
{
  "success": true,
  "message": "Dirección actualizada correctamente."
}
```

## Enhanced

### 1. Descripción de la Funcionalidad (Flow) Detallada

#### 1.1 Listar Direcciones del Usuario Autenticado
1. Un usuario autenticado solicita ver su libreta de direcciones.
2. El sistema recupera todas las direcciones asociadas a su `userId`.
3. Retorna un array con todas las direcciones. Si no posee direcciones registradas, el sistema devuelve una lista vacía `[]`.
4. El frontend renderiza las direcciones en tarjetas (cards), destacando visualmente cuál es la predeterminada con una estrella.

#### 1.2 Agregar Nueva Dirección de Entrega
1. El usuario completa el formulario en el frontend (Calle, Número, Localidad, Referencia).
2. **Validación Corporativa**:
   - Si el usuario pertenece a una empresa (`companyId` no nulo):
     - El backend consulta el estado de `allowExtraAddresses` en el modelo `Company`.
     - Si `allowExtraAddresses = false`, el backend rechaza la petición con un error `403 Forbidden` indicando la restricción corporativa. El frontend deshabilita los controles de creación y muestra un aviso restrictivo.
3. Si es la primera dirección registrada por el usuario, se establece automáticamente como `isDefault = true`. Si ya existen direcciones, se registra como `isDefault = false`.
4. Al completarse con éxito, se responde con un código de estado `201 Created` y los datos de la dirección guardada.

#### 1.3 Editar Dirección de Entrega
1. El usuario puede modificar los campos `street`, `number`, `locality` y `reference` de una dirección que le pertenezca.
2. No se permite la mutación directa del campo `isDefault` mediante este endpoint de edición (debe usarse el endpoint de predeterminación dedicado).
3. Tras una edición exitosa, se actualiza el registro en la base de datos y se retorna un código `200 OK`.

#### 1.4 Eliminar Dirección de Entrega y Lógica de Re-predeterminación
1. Un usuario puede eliminar cualquiera de sus direcciones que le pertenezca.
2. **Validación de Dirección Única**:
   - Si es la única dirección registrada y está marcada como predeterminada, la eliminación se rechaza con un código `400 Bad Request` ya que cada usuario debe poseer al menos una dirección.
3. **Lógica de Promoción de Predeterminada**:
   - Si la dirección que se elimina está marcada como `isDefault = true` y existen otras direcciones en la libreta del usuario:
     - El sistema promueve automáticamente la dirección más antigua restante (menor ID) como la nueva predeterminada (`isDefault = true`).
     - Toda esta operación (eliminación y actualización de la nueva predeterminada) se ejecuta atómicamente dentro de una transacción de base de datos.
4. **Caso Especial B2B (Desasociación Corporativa)**:
   - Cuando un empleado es removido de una empresa (pasa a estado `inactive`), el sistema remueve automáticamente su dirección corporativa de entrega.
   - Si esa dirección corporativa era la predeterminada, el backend busca en la libreta de direcciones del usuario y promueve a predeterminada la última dirección agregada anteriormente por el usuario (la de mayor ID).

#### 1.5 Cambiar Dirección Predeterminada (Toggle Atómico)
1. El usuario presiona el botón para marcar una dirección de su libreta como la predeterminada.
2. Para evitar condiciones de carrera o estados con múltiples direcciones predeterminadas, el backend ejecuta la acción dentro de una transacción de base de datos en dos pasos secuenciales:
   - Limpia el campo `isDefault = false` para todas las direcciones del usuario (`clearDefaultByUserId`).
   - Establece `isDefault = true` únicamente para la dirección solicitada.
3. Retorna un código `200 OK` tras completar la transacción.

#### 1.6 Reglas de Ciclo de Vida y Trazabilidad B2B
Para mantener el historial consistente de pedidos y evitar pérdidas de trazabilidad al dar de baja a empleados y administradores corporativos, se definieron las siguientes políticas de negocio:
1. **Prerrequisito de Empleado para Administrador**: Para asignar a un usuario como administrador (`CompanyAdmin`) de una empresa, primero debe haber sido agregado como empleado (`CompanyEmployee`).
2. **Baja Lógica (Traceability)**: Cuando se quita a un empleado o administrador de una empresa, los registros en las tablas correspondientes no se borran físicamente. Se actualiza su estado (`status`) a `'inactive'`. Esto preserva el historial de pedidos y relaciones contractuales.
3. **Prevención de Auto-baja**: Ningún administrador o empleado puede darse de baja a sí mismo de su propia empresa (el botón de remoción se deshabilita para el propio usuario autenticado, y el backend rechaza la petición con código `403`).
4. **Secuencia de Baja de Administrador**: Si un empleado es además administrador activo de la empresa, no puede ser removido de la lista de empleados directamente. Primero debe ser revocado de su rol de administrador, y luego dado de baja como empleado.

### 2. Estructura de Endpoints y URLs Detallada

#### 2.1 Obtener direcciones del usuario: `GET /api/users/me/addresses`
- **Headers**: Requiere cookie de sesión con JWT válido.
- **Success (200 OK)**:
```json
{
  "success": true,
  "message": "Direcciones obtenidas exitosamente",
  "data": [
    { "id": 4, "street": "Av. Belgrano", "number": "120", "locality": "Lules", "reference": "Casa", "isDefault": true }
  ]
}
```
- **Error (401 Unauthorized)**: Sesión inválida o expirada.

#### 2.2 Agregar dirección: `POST /api/users/me/addresses`
- **Request Body**:
```json
{
  "street": "San Martín",
  "number": "450",
  "locality": "Lules",
  "reference": "Trabajo"
}
```
- **Success (201 Created)**:
```json
{
  "success": true,
  "message": "Dirección creada exitosamente",
  "data": { "id": 5, "userId": 1, "street": "San Martín", "number": "450", "locality": "Lules", "reference": "Trabajo", "isDefault": false }
}
```
- **Error (400 Bad Request)**: Datos inválidos o incompletos (validados por Zod).
- **Error (403 Forbidden)**: La cuenta corporativa tiene `allowExtraAddresses = false` y el usuario ya posee al menos una dirección.

#### 2.3 Editar dirección: `PUT /api/users/me/addresses/:addressId`
- **Request Body**:
```json
{
  "street": "San Martín Modificado",
  "number": "452"
}
```
- **Success (200 OK)**:
```json
{
  "success": true,
  "message": "Dirección actualizada exitosamente",
  "data": { "id": 5, "userId": 1, "street": "San Martín Modificado", "number": "452", "locality": "Lules", "reference": "Trabajo", "isDefault": false }
}
```
- **Error (404 Not Found)**: La dirección no existe o no pertenece al usuario autenticado.

#### 2.4 Eliminar dirección: `DELETE /api/users/me/addresses/:addressId`
- **Success (200 OK)**:
```json
{
  "success": true,
  "message": "Dirección eliminada exitosamente",
  "data": null
}
```
- **Error (400 Bad Request)**: Se intentó eliminar la única dirección predeterminada del usuario.
- **Error (404 Not Found)**: La dirección no existe o no pertenece al usuario.

#### 2.5 Establecer predeterminada: `PUT /api/users/me/addresses/:addressId/default`
- **Success (200 OK)**:
```json
{
  "success": true,
  "message": "Dirección predeterminada actualizada exitosamente",
  "data": { "id": 5, "isDefault": true }
}
```
- **Error (404 Not Found)**: La dirección no existe o no pertenece al usuario.
