## Enhanced

### 1. User Story
**Como** Administrador de Javiandas
**Quiero** gestionar la vinculación de empresas, administradores de empresa y empleados corporativos
**Para** configurar el modelo comercial B2B y los accesos de cada organización antes de que sus usuarios se registren en la plataforma.

### 2. Descripción de la Funcionalidad (Flow)

El panel de asignación corporativa es el pilar fundamental del modelo B2B de Javiandas. Permite al administrador de la plataforma crear empresas clientes, asignarles administradores delegados y pre-asignar la nómina de empleados que podrán registrarse como usuarios corporativos (**US-03**).

#### Flujo de Configuración de Empresa:
1. El Admin de Javiandas ingresa al **Panel Corporativo** (ruta protegida por `requireAuth` + `requireRole('admin_javiandas')`).
2. Visualiza un listado paginado de empresas registradas con columnas: Nombre, CUIT, Tipo de Beneficio, Cantidad de Empleados, Estado (Activa/Inactiva).
3. Hace clic en "Crear Empresa" y se abre un formulario modal con los campos obligatorios.
4. Completa: **Nombre**, **CUIT** (con validación de formato XX-XXXXXXXX-X), **Dirección Física Principal** (Calle, Altura, Localidad), **Tipo de Beneficio** (selector: `Corporativo` | `Corporativo Premium`) y **Permitir Direcciones Extras** (toggle boolean, por defecto `false`).
5. El frontend valida en tiempo real (Zod schema en el cliente) antes de enviar.
6. El backend valida nuevamente con Zod, verifica unicidad de CUIT, y persiste la empresa.
7. Tras creación exitosa, se redirige a la pantalla de detalle/perfil de la empresa recién creada.

#### Flujo de Edición de Empresa:
1. Desde el listado o desde el perfil de la empresa, el admin puede editar los campos de la empresa.
2. El CUIT no puede ser modificado una vez creado (campo de solo lectura).
3. Al guardar, el backend aplica las mismas validaciones que en la creación (excepto unicidad de CUIT).

#### Flujo de Asignación de Admins de Empresa:
1. En el perfil de la empresa, hay una sección "Administradores" con un listado de los admins asignados.
2. El admin de Javiandas busca un usuario por email en un campo de búsqueda.
3. Si el email existe en la tabla `users`, se le asigna el rol `admin_empresa` vinculado a esa `companyId`. Se permite **más de un admin** por empresa.
4. Si el email NO existe en la tabla `users`, el sistema muestra un mensaje: *"Este email aún no tiene cuenta registrada. Se asignará automáticamente cuando el usuario se registre"*, y se guarda como pre-asignación pendiente.
5. Un admin de empresa puede ser removido de la empresa (sin eliminar su cuenta de usuario).

#### Flujo de Pre-asignación de Empleados (Batch):
1. En el perfil de la empresa, hay una sección "Empleados Pre-asignados".
2. El admin de Javiandas puede cargar emails de forma **individual** (input + botón "Agregar") o **masiva** (textarea separado por comas/saltos de línea, o carga de archivo CSV).
3. El backend valida cada email (formato correcto, no duplicado dentro de la empresa ni asignado a otra empresa).
4. Emails inválidos o duplicados se reportan de vuelta con detalle, sin bloquear los válidos.
5. Los emails pre-asignados se guardan en la tabla `company_employees` con estado `pending`. Cuando el empleado se registre (**US-03**), el sistema lo reconocerá y lo vinculará automáticamente.
6. El admin puede eliminar emails pre-asignados (solo si el empleado NO se ha registrado aún).

### 4. Estructura de Endpoints y URLs

> **Nota**: Todos los endpoints de esta US están protegidos por el middleware `requireAuth` + un nuevo middleware `requireRole('admin_javiandas')`. Las cookies `HttpOnly` ya implementadas en **US-01** se reutilizan como mecanismo de autenticación.

#### 4.1 Obtener listado de Empresas: `GET /api/admin/companies`
- **Query Params (opcionales)**: `page`, `limit`, `search` (búsqueda por nombre o CUIT).
- **Success Response (200 OK)**:
```json
{
  "success": true,
  "message": "Empresas obtenidas correctamente",
  "data": {
    "companies": [
      {
        "id": 1,
        "name": "ACME S.A.",
        "cuit": "30-12345678-9",
        "locality": "Lules",
        "benefitType": "Corporativo Premium",
        "employeeCount": 15,
        "isActive": true
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 10,
      "total": 1
    }
  }
}
```

#### 4.2 Obtener detalle de una Empresa: `GET /api/admin/companies/:companyId`
- **Success Response (200 OK)**:
```json
{
  "success": true,
  "message": "Empresa obtenida correctamente",
  "data": {
    "company": {
      "id": 1,
      "name": "ACME S.A.",
```

#### 4.3 Crear Empresa: `POST /api/admin/companies`
- **Request Body**:
```json
{
  "name": "ACME S.A.",
  "cuit": "30-12345678-9",
  "street": "San Martín",
  "addressNumber": "123",
  "locality": "Lules",
  "benefitType": "Corporativo Premium",
  "allowExtraAddresses": false
}
```
- **Success Response (201 Created)**:
```json
{
  "success": true,
  "message": "Empresa creada correctamente",
  "data": {
    "company": {
      "id": 1,
      "name": "ACME S.A.",
      "cuit": "30-12345678-9",
      "street": "San Martín",
      "addressNumber": "123",
      "locality": "Lules",
      "benefitType": "Corporativo Premium",
      "allowExtraAddresses": false,
      "isActive": true
    }
  }
}
```
- **Error de Validación (400 Bad Request)**:
```json
{
  "success": false,
  "message": "Formato de CUIT inválido. Use el formato XX-XXXXXXXX-X",
  "data": null
}
```
- **Error de Duplicado (409 Conflict)**:
```json
{
  "success": false,
  "message": "Ya existe una empresa con el CUIT 30-12345678-9",
  "data": null
}
```

#### 4.4 Actualizar Empresa: `PUT /api/admin/companies/:companyId`
- **Request Body** (mismos campos que creación, excepto `cuit` que se ignora):
```json
{
  "name": "ACME S.A. (Actualizada)",
  "street": "Belgrano",
  "addressNumber": "456",

```
- **Success Response (200 OK)**:
```json
{
  "success": true,
  "message": "Empresa actualizada correctamente",
  "data": { "company": { "...campos actualizados..." } }

```

#### 4.5 Asignar Admin de Empresa: `POST /api/admin/companies/:companyId/admins`
- **Request Body**:
```json
{
  "email": "admin@acme.com"
}
```
- **Success Response (201 Created)**:
```json
{
  "success": true,
  "message": "Administrador asignado correctamente",
  "data": {
    "admin": { "id": 1, "email": "admin@acme.com", "status": "active" }
  }
}
```
- **Success Response (201 Created) — Usuario no registrado aún**:
```json
{
  "success": true,
  "message": "Administrador pre-asignado. Se vinculará al registrarse.",
  "data": {
    "admin": { "id": 2, "email": "nuevo@acme.com", "status": "pending" }
  }
}
```

#### 4.6 Remover Admin de Empresa: `DELETE /api/admin/companies/:companyId/admins/:adminId`
- **Success Response (200 OK)**:
```json
{
  "success": true,
  "message": "Administrador removido correctamente",
  "data": null
}
```

#### 4.7 Pre-asignar Empleados (Batch): `POST /api/admin/companies/:companyId/employees/batch`
- **Request Body**:
```json
{
  "emails": ["emp1@acme.com", "emp2@acme.com", "invalido", "emp1@acme.com"]
}
```
- **Success Response (200 OK)** — Respuesta parcial con detalle:
```json
{
  "success": true,
  "message": "Procesamiento completado",
  "data": {
    "added": ["emp1@acme.com", "emp2@acme.com"],
    "errors": [
      { "email": "invalido", "reason": "Formato de email inválido" },
      { "email": "emp1@acme.com", "reason": "Email duplicado en esta solicitud" }
    ],
    "summary": { "total": 4, "successful": 2, "failed": 2 }
  }
}
```

#### 4.8 Remover Empleado Pre-asignado: `DELETE /api/admin/companies/:companyId/employees/:employeeId`
- **Error si ya está registrado (409 Conflict)**:
```json
{
  "success": false,
  "message": "No se puede eliminar un empleado que ya se registró en la plataforma",
  "data": null
}
```

#### 4.9 Respuestas de Error Comunes
- **No autenticado (401 Unauthorized)**:
```json
{ "success": false, "message": "Not authenticated", "data": null }
```
- **Sin permisos (403 Forbidden)**:
```json
{ "success": false, "message": "Acceso denegado. Se requiere rol admin_javiandas", "data": null }
```

### 8. Requerimientos No Funcionales
*   **Seguridad**: Todos los endpoints requieren autenticación (cookie JWT vía **US-01**) y autorización por rol `admin_javiandas`. Validación doble (cliente + servidor) con Zod.
*   **Validación de CUIT**: Regex `^\d{2}-\d{8}-\d{1}$` tanto en frontend como en backend.
*   **Idempotencia del Batch**: El endpoint de pre-asignación de empleados debe ser parcialmente idempotente: si un email ya está pre-asignado a la misma empresa, se ignora sin error; si está asignado a otra empresa, se reporta como error.
*   **Performance**: El listado de empresas debe soportar paginación server-side para evitar consultas masivas.
*   **Atomicidad**: La operación batch debe correr dentro de una transacción de Sequelize. Si se produce un error inesperado (no de validación), se hace rollback completo.

### 9. Estilo Visual y Assets
*   **Estilo Visual**: Consistente con el tema oscuro y la paleta verde claro establecidos en la **US-01**. El Panel Corporativo debe usar la misma tipografía, bordes redondeados y micro-animaciones de hover/focus del sistema de diseño existente.
*   **Tabla de listado**: Usar diseño con zebra-striping sutil, hover-row, y badges de color para el `benefitType` (verde para Corporativo, dorado para Premium).
*   **Formulario Modal**: Glassmorphism con backdrop-blur, transición de entrada/salida suave (150ms ease).
